# 为什么身份、灯牌和正文是独立节点

直播消息经常同时包含昵称、用户等级、粉丝身份、灯牌和正文。把它们提前拼成一段字符串会
丢失语义，也会迫使所有信息共享同一种颜色和布局。

LiveFlow 保留结构：

```text
[身份节点] [等级节点] 昵称：正文
```

每个身份拥有自己的 `kind`、标签、等级、变体和可选资源 key。引擎不根据一种身份推断另一
种身份，也不把等级颜色扩散到整条正文。

## 结构化节点带来的能力

- 灯牌可以使用胶囊布局，正文仍保持高对比度；
- 缺失某个身份时只省略对应节点；
- 图片资源必须经过调用方的 asset resolver；
- reduced motion 和紧凑模式可以独立隐藏高成本节点；
- 自定义 renderer 可以扩展某种身份，而无需重写整条消息。

## 安全边界

所有上游文字都作为文本节点写入，不接受任意 HTML。`assetKey` 不是 URL；只有调用方提供的
resolver 可以把它映射成允许加载的资源。resolver 拒绝时省略该资源节点，不把上游值直接
写入 `src`。

这种结构既保留灯牌的视觉语义，也避免把平台原始 payload 带进通用引擎。
